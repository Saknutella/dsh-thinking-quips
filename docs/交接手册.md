### 3.4 用时:`conversation.chat.turnTail` 座位 + 官方格式化

- **时钟优先级(0.9.1 定案):① DSH 自己那条标签 ② 座位 ③ 自计时器。**
- ① **首选读 DSH 自己的用时**:DSH 从自己的 store 拿运行回合起点、并**每秒把标签重写**成
  `深度求索中，用时 10分46秒 ···` / `Deep diving for …`;插件只是用 CSS 把它藏起来、**没有删掉**,所以那个权威值一直在 DOM 里。
  `durationFromText`/`labelDuration` 用插件**同一套单位词表**(见下)把它读回来,`elapsedFrom` 优先采用 —— 这也是三条来源里
  **唯一扛得住页面刷新**的一条(刷新会重建插件,但不会重建 DSH 的 store)。用户实机反馈:插件显示 8分27秒、DSH 自己那条显示 10分46秒,
  差值正是「上次刷新到现在」。
- ② 座位 `conversation.chat.turnTail`(list / **session** 作用域,props `{ turn: TurnLocation, seq, openFile }`)只作兜底:
  它**每个回合尾部各挂一份**、已结束回合的尾部也留在 DOM 里,所以必须自己判断进行中 —— 只接受 `turn.status === "open"`
  (DSH 自己的运行时钟就是这条规则,`ChatView.runningStartTime`)、`start.time` 必须是有限数字、旧回合不得把时钟往回拨、
  槽里那个回合一旦不再 open 就交还。①读不到(`runningText` 缺失或标签无 duration)时才用它。
- ③ 自计时器是最后兜底(0.7.0 之前的行为)。**运行行离场只重置自计时器,绝不动官方槽**:重渲染/刷新都会让运行行短暂不在,
  清了就会「中途刷新从 0 重新计时」(0.9.1 第一版修复踩过的坑)。
- 格式化与官方 `formatRunDuration` 对拍 **13 组零差异**(zh/en 各半,含 en 单位尾随空格 → `1m 0s`);`durationFromText` 是同一套词表的反向解析。
### 3.5 运行面:`<html data-platform>` 与 `dshDesktop`(本次新增)

- 两个第一方信号:**`"dshDesktop" in globalThis`**(Electron preload 桥,最先装上 → 优先)与
  **`<html data-platform>`**(值是**来访设备**的 OS:`darwin`/`win32`/…,不是服务端的)。
- `data-platform` **可能晚到 `DOMContentLoaded`** → 必须在 `apply()` 里读一次 **并** 观察它的变化
  (`watchSurface`,只监听 `documentElement` 的这一个属性);没有 `MutationObserver` 时降级为 no-op,读到的初值仍然有效。
- 运行面是**运行时事实,不是用户偏好**:存在**不落盘的** `runtimeStore`(与 `makeStore` 分开,后者会写 localStorage),
  并只读回显在设置行(`data-tq-surface`/`data-tq-platform` + 文案)。纯 UI 插件不必按运行面分叉(AGENTS §6 只要求知道)。

### 3.8 协作者 sprite(8 个,0.11.0)

- **位置**:几何在 `LOADER_SPRITES`(一张表:24 单位 viewBox 的原始坐标,不取整),绘制是唯一的
  `ensureSprite()`;样式表里 `.tq-loader-jelly,…{display:block;width:1em;height:1em}` +
  `.tq-loader-sprites svg{width:1em;height:1em}` ⇒ 与插件自有图标同一套字号绑定(`em`),标记是
  span 上的 `tq-loader-sprites`。
- **动画**:全部写在插件样式表里(交付件自带的 `<style>`/`<title>` **不移植**),每条时长都是
  `calc(1.6s / var(--tq-speed,1))`(两家族共用节奏;多部件图标每个部件用同一表达式,否则变速时锁相会散)。
  `tickTock` 与 `pinwheel` 都补了交付件缺的 `transform-origin:0 0`(否则摆杆绕自身盒心转、风车绕轮毂外的位置转,而不是绕轴/轮毂)。
- **px 一律不许出现**:SVG `transform` 里的无单位长度是 viewBox 单位,而 `px` 是设备像素;交付件的
  `translateY(4.6px)` / `translateX(10.4px)` 已改成无单位。自检 `test-loaders.mjs` **遍历整张表**断言没有任何
  值含 `px`,并要求每个被样式表动画的 class 都带 `tq-sprite` 标记。

### 3.11 运行图标的尺寸契约(2026-10 实测)

字号是用户**可以全局设置**的,DSH 用一条变量把它公开出来(chart bundle 里实测):

```
--dsh-content-font-delta = calc(var(--dsh-content-font-size, 14px) - 14px)
官方运行图标(宽=高)      = 14px + delta     → 默认 14px;字号 15px 时 15px
运行行的行盒              = 22px + delta
```

实测(字号 15px → delta 1px;用插件 `preview/animations.html` 改 root 上的
`--dsh-content-font-delta` 后读 `getComputedStyle().fontSize` 与 `getBoundingClientRect()`):

| 谁 | delta 0 | delta 1 | delta 4 | 说明 |
| --- | --- | --- | --- | --- |
| 插件自绘的 7 种 | 16px | **17px** | 20px | 基数 `calc(16px + delta)`;ladder(`--tq-loader-scale` 0.8/1/1.25)再乘上去 |
| 官方 `native` 盒子 | 14px | 15px | 18px | 它自己的公式 `calc((14px + delta) * scale)` |
| 挂载节点的 `font-size` | 继承值(14px) | 继承值(14px) | 继承值(14px) | **说明我们的基数没有污染官方节点** |

契约三条:

1. **自绘图标的基数只声明一次**:`.tq-loader-orbit,…,.tq-loader-fish{font-size:calc(16px + var(--dsh-content-font-delta,0px))}`,
   内部几何全部用 `em`(`.25em` 的轨道格、`1em` 的环/形、`1.25em × .92em` 的官方 logo)。**任何一处写回 px,就在字号变化时冻回 16px** —— `test-loaders.mjs` 末尾那段断言会拦住。
2. **不要写进共享 transform**:CSS 的 `calc()` 不允许"长度 ÷ 长度",所以基数没法折进 `transform: scale()`;用 `font-size` + `em` 是唯一声明式的做法(**不需要 JS 观测**,设置一变浏览器自己重算)。
3. **`stateDot` / `native` 故意排除在基数选择器之外**:它们是 DSH 自己的节点,自己定尺寸;给它们塞一个我们发明的 `font-size` 会改变官方组件的继承环境。`native` 的 `:empty`(APNG mask)分支也必须带 delta —— 2026-10 之前它漏了,是同一条契约里的不一致。

再验一遍:改 root 的 `--dsh-content-font-delta` 为 `0px/1px/4px`,读那 7 个样式的 `fontSize` 应为 `16/17/20px`,同时给 `.tq-loader-native` 与 `.tq-loader-stateDot` 各塞一个空探针,它们的 `fontSize` 应当**保持继承值**(见上表)。

| **官方扫光的"亮度"是它自己的 token** | `glow`(0–100)→ `mixToWhite(base, glow/100)` → 写 `--dsw-alias-label-shimmer`;默认色 + 默认亮度时**什么都不写** | 亮度不是"插件另加的一层":官方组件的高光就吃这个 token,所以这个控件直接作用在官方扫光上。0 = 与文字同色(看不出扫光)、100 = 纯白;预览页第 5 节用**官方原样 CSS** 复刻了这个组件,可以直接拖着看 |
| 速度 | 只缩放插件自己的动画(`--tq-speed`) | 官方扫光的动画在别人的组件里(用户决定不缩放) |
| **官方图标三种** | `stateDot` = 官方 `StateDot`(`ongoing`);`fish` = 官方 logo path 自组 svg;**`native` = 克隆官方鲸鱼节点** | 不重画别人的素材;三种都要靠 §7 里那两个局部名,`native` 还依赖 `runningContent > runningIcon` 的父子关系 |
| **指示图标只有一个** | 只要插件画了图标,就给运行行写 `data-tq-icon`(值 = 实际画出的样式),CSS 据此收掉 DSH 自己那只鲸鱼 | 用户的决定:鲸鱼要是**可选项之一**,而不是永远并排的第二只;`native` 就是把官方那只选回来(§9 第 7 条)。**隐藏只影响观感**,DSH 的节点不动 |
| **官方图标的兜底** | `stateDot → orbit`(0.11.2 移除了插件自带的 `ring`,兜底改到默认样式)、`fish/native → orbit`;`data-style` 保留用户选择、`data-effective` 记实际画的 | fail-soft
| **`native` 是位图,不能靠 transform 缩放** | 尺寸写进盒子(`width/height: calc((14px + font-delta) * var(--tq-loader-scale))`),并给 `.tq-loader-native` 关掉共享的 `transform: scale()` | 鲸鱼是 28×28 APNG 当 alpha mask;`transform` 会在 14px 栅格化后再拉伸位图 → **大尺寸发虚**(用户实测)。按真实像素定尺寸后是 11.2/14/17.5px,全是降采样,清晰。`:empty`(mask)分支同样带 delta —— 2026-10 修掉了它漏掉 delta 的那处不一致 |
| **插件自己画的图标必须跟全局字号** | 自绘 loader 的基数声明一次:`font-size:calc(16px + var(--dsh-content-font-delta,0px))`;内部几何(点/条/鱼/3×3 轨道/8 个 sprite)全用 `em` 或 viewBox 单位,随字号与三档尺寸缩放 |
| **均衡器的三条要量化到整设备像素** | `.tq-loader-bars` 的几何改由 `--tq-bar-w` / `--tq-bar-gap` / `--tq-bar-h` 驱动,`snapBarsGeometry()` 把**基准 × 档位**算成真实像素、按 `1/DPR` 取整后写回;该样式**关掉共享 transform**(`transform:none`),`em` 值保留为无 JS 回退 | `em` 几何在 17px 基准下每条 = 3.1875px = **6.375 设备像素**,而 Chromium **逐条各自**把边对齐设备像素:实测中间那条被画成 **8** 设备像素、两侧 6 → 看起来"中间那条偏左"(用户从设置预览报的)。纯 CSS 试过 `space-between`、`will-change`、`translateZ(0)`、grid 三列,**全都没用**(布局本来就对称,错的是逐边取整);而共用 transform 也不行 —— transform 是"先按布局取整、再缩放",除非 `DPR × scale` 是整数(默认档位下 sm=1.6、lg=2.5 ✗),前后两套边不可能同时落在设备像素上。所以按 `native` 的先例自己定尺寸。实测三档几何:**sm 5/5/5 间隙 3/3、md 6/6/6 间隙 4/4、lg 8/8/8 间隙 5/5**(设备像素,全部对称) |

### 6.3 动画总览页(本次新增,离线肉眼看全部动画)

```powershell

node tools/build-preview.mjs      # 生成 preview/animations.html(~230 KB,自包含)
node test/test-preview.mjs        # 页面是否与当前插件一致(防漂移)
```

- **它不是复刻**:页面把 `lib/client.js` **原样内嵌**并在浏览器里调用插件自己的
  `injectPluginCss()` / `ensureLoader()` / `applyStatusText()` / `apply()`,画在**仿造运行行**上(标记形状与 §3.1 一致)。
- **段落顺序是硬性的**:**实时行必须排在所有仿造行之前**。插件用
  `document.querySelector("[data-chat-running]")` 找自己的行 —— 也就是文档里**第一个**匹配;
  把矩阵放在前面,插件就会去画那个格子(本轮踩过一次:`liveText` 是空的)。
- **`shimmer` 要真的动起来,靠一个最小 React 替身**:官方扫光是 DSH 的 `TextShimmer` 组件,而页面没有 React。
  以前 `requireShim` 故意抛错 → 插件走**降级路径(纯文本)** → 这一节看上去"shimmer 没效果"(用户报的)。
  现在 shim 提供 `createElement` / `createRoot` / 一个只画结构的 `TextShimmer`,让插件的**真实路径**跑起来,
  再由原样内联的官方 CSS 去动画化;官方 CSS 的 `@scope` 同时覆盖 `.tq-shim`(第 5 节)与 `.tq-official`(插件的盒子)。
  缺种子时插件仍降级为纯文本 —— 那才是老外壳的真实行为。
- **第 3 节每行一个插件实例**:插件每个模块只保留**一个**官方 React root(生产环境正确:一条运行行)。
  共用实例时,画第二行会把第一行的 root `unmount()` 掉,第一行的盒子随之被清空、整节看起来空白。
  所以 `buildEffects()` 每行 `boot()` 一次(一行 = 一个外壳)。
- **控件改完立刻生效**:`pushConfig()` 之后调插件的 `forcePass()`(由模块级 `livePass` 登记、卸载时清空),
  不必等插件自己的 600 ms 轮询 —— 否则点一下要等近一秒,体感就是"按钮坏了"(用户报的)。
- **"字体颜色"是两态控件**:`跟随主题(shimmer)` 或自定义。`shimmer` 是插件配置里的**哨兵值**,
  含义是"用 DSH 自己的品牌蓝扫光渐变",不是一种颜色;选自定义才出现取色器。
- **官方素材是构建时提取的**:鲸鱼样式表(含 60 帧 APNG)、官方 logo 路径、**设置导航图标**(齿轮 / 内置插件),
  **以及官方 `TextShimmer.module.css`** 都从**本机安装的 DSH** 里读出来内联,不是手抄;
  找不到 DSH 安装时页面照常生成,只是官方那几格显示回退图标(自检会 SKIP 掉新鲜度断言)。
- **第 4 节有两组图标**:设置导航图标(官方齿轮 / 内置插件 / 官方鲸鱼 / 插件用的那个 —— 后两者本来就是同一份 path,各 16px 与 8×),

  「36×36 的画布由图标自己画、浅色瓦片由清单画」一眼能看出来);
  **第 5 节是官方扫光**:把 `TextShimmer.module.css` **原样**内联(`@scope (.tq-shim)` 限定范围,不改写选择器),

- **诚实标注了三处做不到的事**:`stateDot`(需要 React 运行时→页面显示默认的插件样式)、

| **每次工具调用,俏皮话立刻跳回第一条、动画同时从头开始**(用户实机反馈;截图里图标也落在文字后) | DSH 每次重渲染回合都会**重建运行行元素**,插件的节点随之离开文档。旧代码把"这个元素里还没有图标"当**首次上屏**(`seed`)→ 下标重置为 0 → 文字一变 → 特效容器被重建 → **动画重启**。轮播下标本来就不该与 DOM 绑定 | ① 轮播改为**只由时钟推导**(`quipIndex(now, quipMs, count)`,与 DOM 无关;`pass()` 不再有 `seed` 参数);② `host` 变化时 `adoptNodes()` 把插件自己的 `.tq-loader`/`.tq-line` **搬进新行**而不是重建,并只把官方 React root 的**记账**(`officialHost`)指到搬过去的行上(不重挂 → 扫光不中断);③ 顺带在早退分支补写新行上缺失的 `data-tq-icon`。断言见 `test-adapt-02.mjs` 的 "DSH replaces the running line (a tool call)";浏览器实测:重建后文字逐字不变、`lineAdopted/glowAdopted` 均为 true |
| **`wave` + 随文用时:波浪每秒重启一次** | 随文用时让文字每秒变一次,而 `renderWave` 无条件"清空 + 重建"所有特效项 → 每个 token 的动画每秒重来。这与上面那条是**同一个根因**(重建了带动画的节点) | 新增 `refreshWaveItems()`:token **形状不变**时**原地更新文本**(节点与 `--i` 都不动),形状变了才重建。断言见 `test-adapt-02.mjs` 的 "the wave across the elapsed tick";浏览器实测特效项跨秒**复用**(`itemReused: true`) |
| **只显示图标时:图标跑到文字后面,且颜色和文字不一致**(用户实机截图) | ① 图标一直是**追加**到 `runningContent`;插件自己写文字时(行随后创建)看起来对,而 `indicatorOnly` 把文字交还 DSH 后就落在文字**之后**;② `releaseOwnership` 走 `textTarget` 会**留下一行空 `.tq-line`**,又成了图标的锚点;③ 图标取的是插件自己的颜色,而那行文字是 DSH 的 `--dsw-alias-label-deep-diving` | ① 新增 `iconAnchor(el)` = `.tq-line`,否则 DSH 的 `[class*="runningText"]`,插入与位置校正都用它;② `releaseOwnership` 的现代分支**不建行、清完就删掉空行**(避免"建了又删"的变更);③ `.tq-loader` 颜色改为 `var(--dsw-alias-label-deep-diving, …)`,`paintHost` 在自定义颜色时**额外写** `--dsw-alias-label-deep-diving`(实测官方 `.…_running{color:var(--dsw-alias-label-deep-diving) }`,所以这正好是那一行的文字色)。断言见 `test-adapt-02.mjs` 的 indicatorOnly 段;浏览器实测:图标在文字左侧、两者同为 `rgb(255,0,0)`(自定义)与 `rgb(43,83,199)`(默认)、无残留空行 |
| **(测试基建)两个 DOM 桩的 `insertBefore` 不忠实** | `insertBefore` 在**移除旧位置之前**就解析参考下标,而"把前面的节点搬到参考节点之前"会因为下标左移而晚一格;`test-loaders` 的桩甚至不从旧父节点摘除(会复制节点)。于是"位置到底对不对"这件事在自检里是被桩伪造的 | 两个桩都改成"先摘除、再定位",与真 DOM 一致。改完 test-adapt-02 立刻暴露出我一开始对锚点的判断偏差 —— 插件逻辑本来就是对的,是桩在说谎 |

**行为差异(用户可见)**:

- `loader` 下拉从 6 项变 **9 项**,多了「官方状态点(旋转)」「官方鲸鱼标志(静态)」「官方鲸鱼(动态)」。
- **状态行上只有一个指示图标了**:以前插件图标与 DSH 的鲸鱼并排出现,现在插件画图标时会把 DSH 那只收起来
  (第 7 条);想要官方那只就选「官方鲸鱼(动态)」——它是 clone 出来的官方节点,动画一样。
- 设置行控件在 0.2 上换成官方组件(观感统一),老外壳自动退回原样式。
- 设置行**多了一行只读的「运行环境」**,并写进 DOM(`data-tq-surface`/`data-tq-platform`)。
- **文字特效从 4 项减到 2 项**(扫光 / 波浪):`official` 与 `glow` 都退场 —— 前者只是 `shimmer` 的别名,
  后者与官方扫光并排看不出区别(用户实测)。旧配置里存的 `official`/`glow` **自动落到扫光**,不用手动改。
- 设置行里的**「发光强度」控件消失**(它只调那个自绘渐变;0.1.x 的旧渐变改用固定高光,观感不变)。
- 设置行里 `quips.speed.fast` 那行原先挤了两个键,已拆开(纯格式修复)。
- **设置项从「通用设置」里的一行搬到设置导航的独立一页「俏皮话」**(设置 → 俏皮话)。导航里那一行显示的是插件自绘的鲸尾图标
  (DSH 给未知分栏回落齿轮,所以由插件标记自己的行并用 CSS 顶替;DSH 若改了导航行结构就会退回齿轮,功能不受影响)。
- 中文界面下导航标签是 **俏皮话**,英文界面下是 **Playful quips**(label 是 thunk,跟随语言,不需要重注册)。
- **「只显示图标」现在是对的**:图标在 DSH 文字**左侧**、颜色与那行文字一致(默认都走 DSH 的运行行文字色,自定义颜色时一起变),不再留下空行。**这个选项保留**——它是插件唯一能与"另一个接管状态文字的插件"共存的方式(0.2.0 的原始用途);两个缺陷都在共用机制里(锚点、颜色 token),修好之后普通模式也一并受益。
